## 预先固定的选择与试验

从原始逐题结果中选取“基座严格通过、适配器严格失败”的题。将适配器原输出达到 512 token 上限与未达到上限分成两层，各用 Python `random.Random(20261031).sample` 无放回抽取 15 题，共 30 题。抽样规则、入选 key 和原始响应保留在本地 `reports/local/.../investigation/`，公开仓库只保留小型选择清单与汇总结果。

在同一适配器、同一 Qwen3 非思考模板上做两项诊断：

1. 贪心解码，将 `max_new_tokens` 从 512 扩至 1,024。对每题检查延长后的解码文本是否以原运行回答为前缀；原运行没有保存 token ID，故只能做文本前缀核对。若不一致，不能把分数变化归因于长度上限。
2. 保持 512 token 上限，改用 Qwen3 模型卡建议的非思考采样参数：temperature 0.7、top_p 0.8、top_k 20。每题重置为 `42 + key` 的随机种子。单次采样只用于诊断，不能证明一般采样效果。

对 30 题使用原始固定版本的 IFEval 严格评分函数；基座沿用原 512 token 回答。两种诊断都报告 capped/uncapped 两层的通过数、重复比例和输出长度。样本由原失败集合选出，不能外推至 541 题总体。
