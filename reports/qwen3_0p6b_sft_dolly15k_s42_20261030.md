# Qwen3-0.6B × Dolly 15k：LoRA SFT 实验复盘

状态：**完成，主指标显著下降**。报告时间：2026-10-31 CST。实验 ID：`qwen3_0p6b_sft_dolly15k_s42_20261030`。

一句话结论：在预先固定的 IFEval 541 题严格提示级指标上，Dolly 15k LoRA SFT 比基座低 **19.04 个百分点**（配对 bootstrap 95% CI：−23.66 至 −14.60 个百分点），虽降低了 Dolly 留出集回答 token NLL，但不能声称通用指令遵循能力提升。

## 问题与方法

- 问题：一轮 Dolly 15k 非思考模式 LoRA SFT 能否提高 Qwen3-0.6B 的独立指令遵循能力？成功条件是在 IFEval 严格提示级通过率上的配对差值为正，且 95% 区间下界大于 0。完整锁定协议见实验 `plan.md`。
- 基座：`Qwen/Qwen3-0.6B`，Hub commit `c1899de289a04d12100db370d81485cdf75e47ca`，Apache-2.0。Dolly 15k：Hub commit `bdd27f4d94b9c1f951818a7da7fd7aeea5dbff1a`，CC-BY-SA-3.0，源文件 SHA-256 `2df9083338b4abd6bceb5635764dab5d833b393b55759dffb0959b6fcbf794ec`。按指令加上下文归一去重 203 条，未发现与 IFEval 完全相同的提示；种子 42 固定为训练 13,328、验证 740、测试 740 条。划分 SHA-256 见 `split_manifest.json`。
- 训练：BF16、LoRA r16/alpha32，q_proj/v_proj，batch 1，梯度累计 16，有效 batch 16，833 步，1 epoch，学习率 2e-4，最大 1,024 token；Qwen3 `enable_thinking=False`，仅回答 token 计损失。每 100 步保留可恢复检查点，最多 2 个；第 2 步检查点的恢复试跑成功。正式训练成功后导出并校验适配器，删除正式临时检查点。
- IFEval：Google Research 提交 `697787053593d98a82f0ffb008463f0eab81ff85`，541 题，输入 SHA-256 `67ffeee0fcb87c317c5b08a2de85557b4a7e96ada6178aa645b4954fe4b53d49`。基座和适配器使用相同非思考模板、BF16、贪心解码、最多 512 个新 token 和官方严格评分函数；语言检测种子 0。对逐题配对差值做 10,000 次 bootstrap，种子 42。IFEval 与 Dolly 的留出测试集各自独立，不把 Dolly 测试集称为官方 benchmark。
- Dolly 验证/测试：两模型对相同样本计算回答 token 加权 NLL；提示已占满 1,024 token 的样本共同排除。未开展人工盲评；对典型题做了非盲抽查。

## 结果

| 指标与样本量 | 基座 | LoRA 后 | 差值 / 不确定性 |
| --- | ---: | ---: | ---: |
| **IFEval 严格提示级通过率，541 题（主指标）** | **313/541 = 57.86%** | **210/541 = 38.82%** | **−19.04 个百分点；配对 95% CI [−23.66, −14.60]** |
| Dolly 留出测试回答 token NLL，733/740 条有效 | 2.5398 | 2.0622 | −0.4775；越低越好 |
| Dolly 留出测试 perplexity，54,688 回答 token | 12.68 | 7.86 | −4.81 |
| Dolly 验证回答 token NLL，731/740 条有效 | 2.6411 | 2.1741 | −0.4670 |

严格提示级配对结果：基座独过 142 题、适配器独过 39 题、双方都通过 171 题、双方都未通过 189 题。训练平均损失 2.094；它不是与基座可直接比较的指标。第 400、800 步及训练结束的 TRL 内置 `eval_loss` 均为 `NaN`，因为验证集有 9 条提示占满 1,024 token、没有被监督的回答 token。训练损失、梯度和第 400 步适配器权重检查均为有限值；独立验证 NLL 按两模型共同排除 9 条后重算。留出测试集同理共同排除 7 条。训练集有 107 条提示占满上限，约 0.8% 样本没有有效回答监督；187 条完整序列超过上限。这是数据准备的质量局限。

适配器生成 137,523 个新 token，基座 85,657 个；达到 512 token 上限的题数分别为 228 和 56。基座独过的 142 题中，适配器有 76 题达到上限。按含有相应约束的题组统计，首尾约束通过数从 49/66 降到 18/66，格式约束从 99/155 降到 63/155；题组可重叠。非盲抽查中，题号 1021 的适配器未遵守全大写要求；题号 1082 与 1092 出现冗长/重复输出并碰到上限。输出变长与失败相关，但本实验未隔离训练数据、解码长度或适配器结构的单独因果作用。另有 39 题适配器独过，不能据此抵消主指标的整体下降。

## 偏差与复盘

- 与计划不同的决策：内置验证损失在第 400 步出现 `NaN` 后，没有改训练超参数或悄悄重跑；长度审计定位到零监督样本，训练后新增双方同规则的验证集 NLL。公开指标文件将无效 `eval_loss` 记为 `null` 并说明原因。公开运行清单的相对路径格式做了后处理纠正；数据哈希未变。
- 可信结论：这次 LoRA SFT 提高了 Dolly 风格答案的似然，但**降低**独立 IFEval 严格指令遵循率。预先定义的提升条件没有满足。评测只覆盖 541 条 IFEval 和这组固定解码设置；没有人工盲评、语义近似污染审计或多随机种子重复，因此不能泛化到所有任务、推理设置或训练种子。
- 下次改进：在训练前过滤或单独处理提示占满上限的样本，增加回答长度控制与停止行为审计，考虑更高质量的约束遵循数据，并预注册多种子重复。任何新配置应另建实验 ID，不能修改本次已锁定结果。
- 清理限制：自动审批策略拒绝了对本次试跑/恢复验证副本的递归删除；这些副本仅留在本机，未上传 GitHub。正式训练检查点已按策略删除，原共享模型缓存未动。
