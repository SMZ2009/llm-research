# 调查报告：Dolly LoRA 后 IFEval 为什么下降

调查日期：2026-10-31 CST。对应原实验 `qwen3_0p6b_sft_dolly15k_s42_20261030`；本文是事后分析，不修改预注册主指标和原始逐题结果。原实验仍为基座 313/541（57.86%）、LoRA 后 210/541（38.82%），配对差值 −19.04 个百分点，95% bootstrap 区间 [−23.66, −14.60] 个百分点。

## 结论层级

**可以确定的近端现象**：加载 LoRA 后，模型更容易生成长而重复的回答，常触及 512 token 上限，同时在首尾、格式、大小写、长度等可验证约束上失分。这个退步不只是“严格”评分器或 512 token 截断造成的：宽松评分和单条指令评分同样下降，且双方都未触及上限的题中仍有明显退步。

**较有根据、但尚未被单独证明的解释**：Dolly 的训练目标是模仿较宽泛的问答/写作答案，缺少足量的 IFEval 式精确约束示范；单轮 SFT 改善了同域答案似然，同时把启用适配器后的生成分布推离了基座已有的约束遵循行为。贪心解码与这一分布变化可能相互放大，造成循环重复和停止失败。不能仅凭这次单配置实验把责任精确归给 LoRA 结构、学习率、Dolly 数据或解码方式中的某一项。

## 1. 排除“只是评分口径”的解释

IFEval 是对可程序验证的指令评分，严格提示级指标要求一题中的全部约束都满足；该设计与原始[论文](https://arxiv.org/abs/2311.07911)及本地固定版本评分代码一致。原实验按同题、同模板、同贪心解码与同 512 token 上限作配对比较。

| 对照 | 基座 | 适配器 | 说明 |
| --- | ---: | ---: | --- |
| 严格提示级，541 题 | 313（57.86%） | 210（38.82%） | 差 103 题；基座独过 142、适配器独过 39 |
| 宽松提示级，541 题 | 338（62.48%） | 215（39.74%） | 宽松检查下也少 123 题；不是单纯首末行/Markdown 处理问题 |
| 严格指令级，834 条指令 | 563（67.51%） | 423（50.72%） | 单条约束也退步，不只是多约束“全对才过”的放大效应 |
| 仅 1 条约束的 305 题 | 227（74.43%） | 156（51.15%） | 简单题同样退步 |

分类是重叠题组、不能相加：首尾约束从 49/66 降到 18/66，格式从 99/155 降到 63/155，大小写从 43/84 降到 25/84；标点题组则从 23/66 升到 27/66。退步不是所有约束类型等量发生，也不意味着模型完全失去遵循能力。逐题配对记录和聚合审计见本实验本地 `reports/local/.../ifeval_per_sample.jsonl` 与公开 `investigation_audit.json`。

## 2. 输出长度与循环重复是最明显的直接问题

| 生成统计，541 题 | 基座 | 适配器 |
| --- | ---: | ---: |
| 平均新 token | 158.3 | 254.2 |
| 达到 512 token 上限 | 56（10.4%） | 228（42.1%） |
| 回答中重复 4-gram 的平均比例 | 0.161 | 0.519 |
| 重复 4-gram 比例超过 0.2 的题数 | 138 | 359 |

重复指标先按单词/标点分词，再对连续 4 元组计算 `(总数−不同元组数)/总数`；这是近似的文本循环指标，不是语义质量评分。只看每个回答前 100 个分词单位，基座与适配器的均值仍为 0.103 与 0.387，说明差异并非只在长回答尾部出现；少于 100 单位的回答没有补齐，因此这个检查也不是严格等长对照。Dolly 训练答案在全文指标上的均值只有 0.0077，13,328 条中只有 69 条超过 0.2；训练答案较短，这个跨数据集比较会受长度影响。现有证据没有显示模型在直接拷贝大量训练答案中的循环文本，更像是生成过程中的重复，但其成因仍需解码干预检验。

上限确实相关：基座独过而适配器失败的 142 题中，适配器有 76 题触及 512 token。但另外 **66 题没有触及上限**。进一步只看两模型都未触及上限的 306 题，基座通过 187，适配器通过 148，净少 39 题。该分层是按生成后的长度选择，不能当成无偏因果估计，但足以否定“只有截断导致下降”的说法。

非盲个例展示两条不同失败路径：题号 1021 要求两段评论全部大写，适配器仅生成 37 token，却把引用句子保留为小写，属于未碰上限的约束失误；题号 1082 要求恰好两段且以 `***` 分隔，适配器不断重复开头的场景句并生成至 512 token，属于循环加长度失控。题号 1092 的“少于 300 词”短文也在反复列举城市后触及 512 token。个例只用于说明机制，不能代替总体统计；另有 39 题适配器独过，改变后的行为并非一律更差。

## 3. 训练目标与独立评测目标不同

Databricks 的[数据集说明](https://huggingface.co/datasets/databricks/databricks-dolly-15k)将 Dolly 定位为员工编写的八类一般指令/回答，包括开放问答、分类、头脑风暴、摘要等。本次训练划分的类别数中，开放问答 3,326、分类 1,924、一般问答 1,876；这些标签本身不是 IFEval 的精确格式、首尾或计数约束。

本地粗略关键词扫描在 13,328 条训练提示中找到：`exactly` 39 条、`no/without comma` 0 条、全大写相关 1 条、`json` 8 条、`start/end with/in` 32 条。这种正则扫描有漏检和误检，不能把命中数当作真正的约束样本数，但能说明许多 IFEval 约束在这份训练集里缺少直白的同类监督。训练与测试都使用回答 token NLL 时，Dolly 留出测试集从 2.540 降到 2.062，证明适配器更会预测 Dolly 答案；它不证明对独立可验证约束更会遵守。已有研究也发现微调可改善目标任务同时损失其他能力，LoRA 并不能保证免于这种取舍；这只是解释本实验的背景，[相关原始研究](https://arxiv.org/abs/2401.05605)不替代本机因果验证。

两种指标还有输入路径差异。SFT 与 Dolly NLL 在每一步给模型标准答案的前文，优化的是 `−log p(标准答案下一个 token | 提示、标准答案前文)`；IFEval 生成则把模型自己刚生成的 token 继续喂回，最终按约束是否全部满足计分。若输出进入循环，NLL 仍可能较低而自由生成很差。这类训练与推理前文不一致、错误沿生成序列累积的机制在[原始序列学习研究](https://arxiv.org/abs/1506.03099)中已有讨论；[文本退化研究](https://arxiv.org/abs/1904.09751)也指出解码策略本身会显著改变重复。它们提供机制背景，本实验的具体责任仍需下面的受控解码诊断。

## 4. 训练实现审计与已知缺陷

对全部 13,328 条训练记录重新按运行时逻辑生成 Qwen3 非思考模板并 token 化：提示 token 全部是完整序列的前缀，完成部分以 tokenizer 的唯一 EOS `<|im_end|>`（ID 151645）结尾，没有双 EOS；全部提示带非思考的空 `<think>` 前缀。TRL 的[官方 SFT 文档](https://huggingface.co/docs/trl/sft_trainer)明确说明 prompt-completion 数据可只对 completion 算损失；本次设置 `completion_only_loss=True` 与这一机制一致。没有发现系统性模板错位、提示被当作答案监督或重复 EOS 的证据。

确认存在的准备缺陷：107 条训练提示本身占满 1,024 token，没有有效回答 token；187 条训练序列被截断，EOS 不在模型实际看到的部分。它们分别占训练集约 0.8% 和 1.4%；验证集同类零监督 9 条导致 TRL 内置 `eval_loss=NaN`，之后已用两模型共同排除的独立 NLL 重算。这些缺陷可能对停止行为有贡献，但没有对照训练，不能从数量小就断言影响一定小，也不能据此把 19.04 个百分点全部归因于它们。详见 `investigation_format_audit.json`。

## 5. 解码设置的可能交互与探索性干预

原实验为了可重复和配对可比，统一使用贪心解码。Qwen3 的[模型卡](https://huggingface.co/Qwen/Qwen3-0.6B)对非思考模式建议 temperature 0.7、top_p 0.8、top_k 20 的采样设置；原实验的贪心设置与该建议不同。这本身不能证明采样会恢复微调后的得分，尤其随机采样也可能损害格式约束。

按固定种子从原本“基座通过、适配器失败”的题中分别抽取 15 道适配器触及上限和 15 道未触及上限的题，做两种事后诊断：贪心但延长上限到 1,024；保持 512 上限改用模型卡建议采样。选择规则和预算见 `investigation_plan.md`。该子集由失败案例选出，结果不能外推为全 541 题的新 IFEval 分数。

| 30 道原失败题的适配器条件 | 原触顶层，15 题严格通过 / 再触顶 | 原未触顶层，15 题严格通过 / 触顶 | 两层合计严格通过 |
| --- | ---: | ---: | ---: |
| 原贪心，512 上限 | 0 / 15 | 0 / 0 | 0/30（按入选条件） |
| 贪心，1,024 上限 | 0 / 15 | 0 / 0 | 0/30 |
| 采样，512 上限，单次种子 | 3 / 10 | 4 / 3 | 7/30 |

延长上限后的 30 份解码文本均以原回答为前缀；原运行未保存 token ID，故只能核对文本。原触顶层的 15 题全部又触及 1,024 token，重复 4-gram 均值由 0.885 升至 0.921，且没有一道恢复通过。这比“恰好在 512 token 截断了本来会正确结束的回答”更支持持续循环或缺少有效停止的解释，但不能排除超过 1,024 token 后的未知行为。未触顶层延长上限后回答和分数均不变，进一步确认了这一层的失败并非 512 上限所致。

采样让原触顶层 3 题、原未触顶层 4 题恢复严格通过；原触顶层平均重复比例降至 0.673，仍有 10/15 题触及 512 token；原未触顶层平均重复比例反而从 0.220 升至 0.259，且出现 3 道新触顶题。这支持“贪心解码与适配器分布有交互，部分题可被其他解码轨迹救回”，同时说明采样并非稳定修复。每题只抽取一次采样轨迹，而且特意筛选原失败题，不能据 7/30 宣称全量通过率增加或把整个 19.04 个百分点跌幅归因于贪心解码。诊断于 10:04:08–10:15:19 CST 完成，退出码 0；逐层结果与入选题号见 `investigation_diagnostic.json`。

## 6. 仍未识别的原因与下一步

本实验只有一个训练种子、一组学习率/LoRA 配置和一份数据，不能估计训练随机性，也无法区分“数据覆盖不足”“学习率/步数过强”“适配器 q/v 选择”“模型自身对贪心解码敏感”各自的因果份额。最直接的后续对照应另建实验 ID：先修复零监督与截断样本，再做相同数据的较低学习率/更早检查点比较；加入专门的可验证约束训练集或混合原本指令数据，并对每个候选都复测原 IFEval 与 Dolly 留出集。不能依据本次事后诊断调整原实验主指标或把一次采样结果写成正式提升。
