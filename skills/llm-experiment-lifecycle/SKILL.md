# LLM 实验全流程

把每次实验做成可预算、可恢复、可复现、可汇报的独立记录。用户已指定 Windows 侧训练工作放在 `D:\Lab\llm-research` 的对应目录；若用户为某次任务明确指定其他项目路径，以该路径为准。先读取当前仓库的 `AGENTS.md`（若有）、`docs/storage_policy.md`、`docs/reproducibility.md`、`.gitignore` 和 Git 状态，沿用项目现有约定。

## 启动前：范围、预算、目录

1. 先界定研究问题、基座与版本、数据和许可、训练方法、基线、独立 benchmark、主指标、成功或停止条件。区分数据集自留测试集与官方 benchmark；不要把训练数据直接称为官方 benchmark。固定数据清洗、去重、划分和随机种子；测试集在协议锁定后才用于最终比较。
2. **在任何耗时训练前**填写 [预算表模板](assets/preflight-budget.md)，估算数据准备、试跑、训练、验证、两模型评测、人工审阅、报告和提交的总历时。训练步数按样本数、有效 batch、GPU 数和 epoch 计算；先用已有运行记录估计吞吐量，试跑后用实测修订，并给出区间和主要不确定性。列出云/API 费用、本机电量及电价公式、增量磁盘和人力时间；未知价格留空并标明假设，不编造金额。把填写后的表单先展示给用户并归档，再启动耗时训练。用户已有授权时无需追加确认；超过已给预算或约束时再询问。
3. 在仓库中使用稳定实验 ID，例如 `<model>_<task>_<dataset>_s<seed>_<yyyymmdd>`。建议映射：`configs/<id>.yaml` 放冻结配置，`experiments/<id>/` 放计划、预算、清单、指标和状态，`reports/<id>.md` 放面向汇报的结论；通用代码放 `src/` 或 `scripts/`，原始数据与划分放 `data/`，适配器放 `models/adapters/<id>/`。不要把本次训练的 Windows 文件散落到仓库外。WSL 虚拟环境、缓存和运行目录可以在 Linux 文件系统中隔离，但记录其位置和清理边界，避免复制已有模型缓存。
4. 在实验清单中记录 Git 提交、模型与数据修订、SHA-256、许可、分割数量、依赖锁文件哈希、GPU、CUDA/PyTorch/Python、种子与配置。保留数据导入来源和官方评测代码版本；公开文件不要包含密钥、机器敏感信息或不必要的绝对本机路径。

## 实施：先验证，再训练，再比较

5. 检查磁盘、显存、驱动、BF16/量化支持、模型加载、任务适用的 chat template 与损失掩码、样本长度和训练/测试泄漏。用小样本试跑验证一个前向、反向、保存与恢复路径，记录真实吞吐量和显存。若改变原计划，更新预算与偏差记录，再冻结正式配置。
6. 正式运行必须有持久日志、可识别的进程/会话和**训练中定期保存的可恢复检查点**；不要只在 epoch 结束保存，也不要让长期训练依赖当前聊天的前台命令。根据单次重算成本设保存间隔与保留数量，验证能够从最近检查点恢复。监控进度、显存、磁盘与异常；失败后先诊断，不悄悄重跑或改超参数。
7. 基座和训练后模型使用同一数据划分、提示模板、推理模式、解码参数、输出上限与评分器。按事先固定的主指标比较，保存每样本结果以便配对分析；有必要时给置信区间和典型失败案例。人工盲评应保留匿名配对、评分准则与揭盲后的统计，明确评审者身份；不能把未完成的评测写成结果。实验质量不足时直接报告局限，不预设微调提升。

## 归档、GitHub 与复盘

8. 完成或中断后填写 [复盘报告模板](assets/postmortem-report.md)：状态、研究问题、实际时长与成本、环境和数据、计划偏差、基线/训练后结果、可信结论、失败原因、下一次改进、复现命令与产物位置。中断的运行标明进度和没有完成的指标。更新预算表中的实测栏，让工作汇报能追溯计划与实际差距。若用户要求只保留导入、不保留实验文件，则在聊天中完成复盘，不额外归档报告。
9. 按仓库的存储策略留存：GitHub 提交计划、预算、冻结配置、必要代码、来源与哈希清单、汇总指标、报告和小型审计记录；原始数据、模型权重、适配器二进制、检查点、虚拟环境、大日志与主机敏感信息默认只留本地或记录可获取位置。提交前检查差异、忽略规则、许可证、文件大小和远端；只暂存本次相关文件，不强推或覆盖他人提交。以实验 ID 关联提交、报告和运行清单。用户已授权此项目的必要内容上传 GitHub，可在验证后推送对应远端；若本次任务另有发布限制，以本次指令为准。
10. 用户取消或要求归零时，停止进程，先做事实复盘，再按明确保留范围处理产物；不得擅自删除原有共享缓存或其他实验。清理前核对实际路径与符号链接，优先可恢复方式；对清理受阻或残留内容如实报告。只保留数据/benchmark 导入时，保留原始输入、官方评分代码及来源哈希，不保留训练划分、适配器或虚构的比较结果。

交付时给出简短结论、关键指标、预算与实测差距、GitHub 提交和本地产物链接；清楚标出未完成项。
